# 团团团项目开发计划

## 1. 项目定位

团团团是一个面向线下社交活动的 AI-LBS 智能拼团推荐小程序。

核心产品主线：

```text
用户不会写筛选条件
→ 用自然语言描述需求
→ AI 转成结构化需求
→ 系统基于真实活动与位置筛选
→ 推荐排序
→ AI 解释推荐理由
→ 用户加入拼团 / 收藏 / 聊天
→ 用户行为反哺推荐
```

第一阶段不追求完整后端和复杂 Agent，先把产品体验跑通：

```text
首页 → 拼团地图 → 需求发布 → AI 解析确认 → 匹配结果 → 拼团详情 → 群聊 → 我的
```

## 3. 技术路线

### 小程序前端

- 使用原生微信小程序。
- 默认使用静态 JS 数据模拟，保留 `local-demo`；后端首期已提供可选 `api` 模式，不要求前端演示依赖网络。
- 页面结构保持轻量，优先跑通用户主流程。
- 后续再将静态数据替换为 API 请求。

### 后端

- 已采用 Django + Django REST Framework。
- 开发期使用 SQLite；生产方向使用 PostgreSQL，Compose 配置已准备但尚未在本机运行。
- LBS 能力：MVP 阶段使用经纬度距离计算；进阶阶段使用 PostgreSQL + PostGIS。
- AI 能力：GLM Provider 适配器、JSON schema 校验和 `glm-5.3` → `glm-5.2` 模型不可用 fallback 已完成；真实请求待密钥。
- RAG：后期再引入 pgvector 或独立向量数据库。

### 图像生成

- 高保真 UI 文字、按钮、标签优先使用本地可复现绘制，避免 AI 生成中文错字。
- 大量视觉资产可使用 `imagegen` 技能生成：
  - 首页插画
  - 活动封面
  - 城市生活方式场景图
  - 头像素材
  - 分享海报背景
  - 地图氛围底图
- 当前本机已有 `imagegen` 技能。
- 若后续环境缺失该技能，可从 GitHub 或 Codex 技能仓库安装后再生成。
- 若使用 CLI fallback，需要本地配置 `OPENAI_API_KEY`，不要把密钥写入代码或聊天记录。

### Phase 6：AI 解析与推荐闭环

当前状态：首期 API 闭环代码已完成，真实 GLM 和端到端模拟器证据待补。

目标：将“自然语言找拼团”从 mock 规则演示推进为服务端结构化解析和事实约束推荐。

AI 解析输入：

```json
{
  "query": "周六下午和3位朋友，找长沙市区5公里内、人均100元以内、安静一点的活动",
  "city": "长沙",
  "lat": 28.193,
  "lng": 112.982
}
```

AI 解析输出（当前 API 契约使用 camelCase）：

```json
{
  "people": 4,
  "period": "下午",
  "maxDistanceKm": 5,
  "budgetPerPerson": 100,
  "preferences": ["安静", "朋友聚会"],
  "city": "长沙"
}
```

推荐逻辑：

- 硬过滤：
  - 城市匹配
  - 活动未结束
  - 人数容量足够
  - 预算不超过限制
  - 距离不超过限制
- 排序：
  - 距离得分
  - 预算匹配度
  - 偏好标签匹配
  - 拼团热度
  - 历史点击/收藏/加入行为
- AI 解释：
  - 只能基于真实活动字段生成。
  - 不允许编造价格、距离、名额、评价。

验收：

- 输入自然语言后能得到稳定结构化条件。
- 推荐结果和解释一致。
- 推荐理由可追溯到真实数据字段。
